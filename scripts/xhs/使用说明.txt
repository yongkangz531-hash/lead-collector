线索采集台 v2 · 使用说明
========================

一句话
  输入行业关键词 → 用你已登录的小红书账号真实打开笔记 → 抓公开评论 →
  本地打分排序 → 配好可以直接发的话术 → 存台账、可导出 CSV、可定时跑。

启动
  双击  启动.bat
    它会做三件事：确认采集专用 Chrome（端口 9333）在跑 → 起本地服务 → 打开界面
  界面  http://127.0.0.1:8788
  第一次用要在这个采集专用 Chrome 里登录小红书（只登一次，profile 会记住）。

页面
  采集        填关键词 + 每轮篇数 → 开始采集。抓完自动出表，可「复制话术」、导出 CSV。
              注意：点行业词只是把词填进去，必须再点「开始采集」才会跑。
  线索库      所有历史线索（去重后），按 高/中/低 筛选，可按词搜索。
  定时监控    给关键词设间隔（分钟），到点自动跑一轮，走的是同一套风控。
              默认 60 分钟一个词，单轮最多 15 篇。
  运行记录    每轮的篇数、新线索、耗时、成败，失败会写原因。
  设置        评论关键词过滤（只留命中词的评论，默认关）+ 当前风控参数。

风控规则（我定的，写死在代码里，就是为了不让你账号出问题）
  1. 只读：只打开笔记看公开评论；不点赞、不关注、不私信。
     原来那套「关注留痕」是写操作，是封号高发点，我改成「台账留痕」：
     记下已采过的笔记和作者，下次自动跳过，不重复打扰同一个人。
  2. 节奏：每篇之间随机 6-9 秒；每 4 篇插入一次 25-45 秒长休。
  3. 上限：单轮最多 15 篇；每小时最多 30 篇；两次任务之间强制冷却 10 分钟。
  4. 时段：23:00-07:00 不采（真人不会半夜刷两小时评论）。
  5. 退避：连续 2 次失败就停 30 分钟，不会硬刷。
  6. 不绕验证码、不改指纹、不并发多账号。弹验证码就停手，人工过。

数据都在这儿（纯文本，可以自己打开看、可以删）
  data/leads.jsonl        所有线索，按内容哈希去重
  data/seen_notes.json    已采过的笔记（去重依据）
  data/authors.json       出现过的作者/评论人
  data/runs.jsonl         每轮运行记录
  data/guard.json         风控计数（删掉等于把冷却/上限清零）
  data/real_<关键词>.json 最近一轮原始评论

常见问题
  「冷却中，X 分钟后再跑」
      正常，防止连跑。等，或者删 data/guard.json 重置。
  「找不到卡片 xxx，跳过」
      搜索结果没渲染到那篇，脚本已自动重搜一次；还不行就换关键词或调小篇数。
  笔记打不开 / 404
      必须真实点击卡片才带 xsec_token；若频繁出现说明登录态掉了，
      去采集 Chrome 里重新登录。
  0 条评论
      那篇笔记本身没人评论，或评论区还没渲染，换关键词再跑。
  想连手机看
      服务只监听本机。要局域网/公网走 cloudflared，别把 8788 直接暴露。

边界（说清楚，免得以为它能干更多）
  只抓「当前关键词搜索结果里、公开可见的评论区」。
  抓不到私信、抓不到别人主页的历史、抓不到需要登录才看得到的内容。
  自动关注 / 自动私信没做，也不建议做——那是最容易被判定成营销号的行为。

文件
  app.py        本地服务（8788）：/api/collect /api/status /api/leads /api/csv /api/config /api/runs
  collect2.py   采集器：CDP 真实鼠标点击，按 id 精确点，后退回列表
  score.py      意向打分 + 需求归类 + 话术模板（词表随便改）
  guard.py      风控闸门（冷却 / 上限 / 安静时段 / 退避）
  store.py      台账（线索去重、已采笔记、作者、运行记录）
  ui/app.html   界面
  启动.bat      一键启动

v3 新增：关注 / 暂停 / 停止 / 换词 / 账号绑定
———————————————————————————

关注（一行一个按钮，点谁关注谁）
  列表最左边一列就是「关注」按钮：
    关注      点一下 → 打开这个人的主页 → 点关注 → 回读确认 → 变成「已关注」
    已关注    已经关注过，不会重复点
    —         这条评论没拿到主页链接（老数据），重新采一批就有了
  单人 3-6 秒间隔，一批最多 20 人，已关注的自动跳过。
  只点「关注」，不点赞、不发私信、不批量关注陌生人。

暂停
  采集中点「暂停」：当前这篇读完后停住，日志不再增加；
  点「继续」接着从下一篇开始跑。暂停期间不会偷偷发请求。

停止采集
  点「停止采集」：秒级停下（实测 2 秒内），不用等这一篇跑完；
  已经采到的评论照样入库，只是不再往下采。

换关键词
  暂停状态下直接改关键词 → 点「换词重跑」：系统先把上一轮停掉，再用新词开一轮。
  也可以点「停止采集」改完词再点「开始采集」。

账号绑定（设置页）
  点「读取当前登录账号并绑定」，从采集浏览器里读出：昵称、userId、小红书号、绑定时间。
  已绑：小红薯6AD66C9D / 95915300252。
  关注用的是这个账号的身份，换账号就在采集浏览器里重新登录再点一次绑定。

v4 新增：评论词库 + 一键评论
———————————————————————————

评论词库（设置页）
  一行一条，序号 1. 2. 3. 4. 自动生成，保存时序号会自动去掉。
  默认 4 条示例，随便改成你自己的口吻。
  别写链接、微信号、电话——那是判定营销最直接的证据。

一键评论
  两种用法：
    列表最左「评论」按钮    点谁，就回复到谁那条评论下面（单独一条，立刻走）
    「一键评论高意向」      自动挑高意向客户，一条一条回复，最多 5 条一批
  流程：打开笔记 → 按「昵称 + 评论前几个字」定位那条评论 → 点它的回复图标 →
  点输入框 → 输入词库里随机一条 → 等发送按钮亮 → 点发送 → 确认输入框清空。
  同一批不会连着用同一句话；评论过的会标「已评论」，不会重复打扰。

风险节奏（这块我压得最狠，因为评论是写操作）
  每条之间 30-60 秒随机；一批最多 5 条；每天最多 15 条；
  采集和评论不能同时做——刚采完要等 10 分钟才能评论。
  平台弹「扫码验证 / 请求太频繁」：程序会立刻停手并提示，
  去采集浏览器里把验证扫了，过 10 分钟再跑。

为什么会被验证
  同一个账号短时间又搜又关注又评论，是平台最敏感的行为组合。
  我实测就撞到一次：发评论时弹「请求太频繁，请一分钟后再试」。
  所以现在是：先采集 → 隔一段时间 → 再关注/评论，一件事一件事做。

v5 桌面软件版（浏览器嵌在软件里）
———————————————————————————

怎么打开
  桌面上的「线索采集台」快捷方式（D:\Desktop\线索采集台.lnk）
  双击就行：软件会自己启动本地服务 + 打开窗口，不用再单独开浏览器。

窗口怎么分
  左边 56%   采集台界面（采集 / 线索库 / 定时监控 / 运行记录 / 设置）
  右边 44%   小红书，就是采集用的那个浏览器，登录态、操作都在这半边里
  快捷键：
    Ctrl+1   只看界面（浏览器收起来）
    Ctrl+2   只看浏览器（界面收起来）
    Ctrl+3   回到分屏
    Ctrl+R   刷新界面

第一次用要登录
  右边那半第一次打开是登录二维码，用手机小红书或微信扫一下。
  只扫这一次，之后一直记住（存在软件自己的配置里，跟你的日常浏览器分开）。
  扫完右边就能正常搜东西，界面上的采集/关注/评论都是在这个内嵌窗口里操作，
  不会再弹新窗口。

数据在哪
  跟之前完全一致：D:\Desktop\安叔-工作台\工具\xhs\data\
  线索、已采笔记、关注记录、评论记录、运行记录都在里面，两个版本共用一份。

和网页版的区别
  网页版：启动.bat → 要另外开一个 Chrome 窗口
  软件版：桌面快捷方式 → 一个窗口搞定，浏览器不会跑出来
  功能没变，风控参数也没变。

v6 控制台版界面（照参考软件布局做的）
———————————————————————————

窗口：左边是小红书（采集就发生在这半边），右边是控制台。

控制台从上到下
  1. 作品地址栏：粘贴 https://www.xiaohongshu.com/explore/... → 进入作品 / 评论采集
     （评论采集 = 只采这一篇的评论；进入作品 = 只在左边浏览器打开看）
  2. 作品信息表：序号 / 发布时间 / 标题 / 链接 / 点赞 / 评论数 / 标签 / 状态
     每次采集完自动记一行，能看到这轮采了哪些笔记、数据量多少
  3. 采集参数：关键词、篇数、开始采集 / 暂停 / 继续 / 停止；监控分钟数 + 开始监控
  4. 过滤参数：点赞≥、评论≥、包含词、屏蔽词、地区、只采 uid 不重复 → 保存参数
     包含词/屏蔽词用逗号分隔；地区按评论的 IP 属地过滤（如 重庆）
  5. 用户信息表：昵称 / uid / IP / 评论时间 / 内容 / 意向 / 状态 / 关注 / 评论
     每行右边两个按钮：点「关注」当场关注，点「评论」当场回一条（词库随机）
     勾选多行后，底部「开始关注」「开始评论」可以批量跑
  6. 底部：评论词库（设置评论内容）、评论间隔、关注间隔、实时关注开关
  7. 最下面：运行日志

导出
  右上「导出作品」「导出用户」直接下载 CSV，Excel 能打开（带 BOM，中文不乱码）

还需要你做的
  左边第一次打开是登录二维码 —— 用手机扫码登录一次，搜索才给看结果。
  扫完点「开始采集」就能跑。

还没做的（做不了/没意义）
  小红书号、粉丝数、性别、年龄：这些不在评论区页面上，要逐个进主页看，
  逐人开主页是最容易被判机器的行为，所以没做，表格里留空。

v7 修复与清空按钮
———————————————————————————

清空列表
  控制台右上角红色「清空列表」：一点清掉作品表 + 用户表 + 已采笔记记录。
  关注记录、评论记录会保留（避免重复关注/重复评论同一批人）。
  采集进行中不能清空，会提示先停止。

修掉的问题
  1. 软件窗口有时不显示、点了没反应
     原因：窗口用了「等就绪再显示」，但子视图不会触发就绪事件，导致窗口一直是隐藏的、
     网页宽度为 0，所有点击都点在空气里。现在改成启动即显示。
  2. 采集老报「没打开目标笔记」或「404」
     原因：小红书卡片里有一个隐藏的 0×0 链接（/explore/id，没有 xsec_token，点了必 404），
     以前点到了它。现在只认可见的封面链接（/search_result/id?xsec_token=...），
     并且失败会再点一次、最后用封面链接兜底。
  3. 用户表里 IP 属地、评论时间一直是空
     原因：这两个值在评论区同一个 .date 容器里，选择器取错了。现已修正。

实测（这一轮）
  搜「装修」29 篇 → 采 3 篇全成功 → 38 条评论，高意向 3
  作品表：发布时间 / 点赞 / 评论数 / 标签 都有值
  用户表：IP 属地（山东、美国、贵州…）、评论时间（09-28、10-10…）都有值

跳过冷却（v8）
  「开始采集」右边的黄色按钮。冷却期内想立刻再跑一轮就点它。
  会先弹一句提醒，确认后才跑。
  它只跳过「两轮之间 10 分钟」这一条；
  每秒间隔、每 4 篇长休、每小时 30 篇上限、23:00-07:00 不采 都还在。
